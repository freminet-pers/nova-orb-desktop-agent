# 公开历史记录

这个目录用于保留可公开、可复核的项目历史，不是本地工作区的倾倒处。历史文档可以解释版本决策和已知边界，但不能扩大当前产品承诺。

## 归档规则

- 只归档能由公开仓库、CI、Issue/PR 或 Release 重新核对的结论。
- 文件名使用 `YYYY-MM-DD-scope.md` 或稳定的版本名；文档开头写明范围、证据来源和仍未验证的事项。
- 任何本机绝对路径、账号标识、API Key、原始照片/视频/录音、数据库、聊天记录、声纹、模型权重、日志、构建包、`release_staging` 和内部阶段报告都不进入公开历史。
- 需要复现的公开截图必须脱敏，并遵循根目录 [CONTRIBUTING](../../CONTRIBUTING.md) 的素材规范。
- 版本发布说明继续放在上一级 `docs/`，因为它们是公开产品记录；本目录只接收独立的过程复盘或决策记录。

当前没有需要公开归档的私人过程材料。保留此索引是为了让未来的公开记录有明确位置，也避免误把本地废料当成项目历史。
